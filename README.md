# GPS Spoofing Detection in ArduPilot

## Overview

This project investigates GPS spoofing detection in an ArduPilot-based navigation system using a Cube Orange+, Here4 GPS, HackRF One, and GPS-SDR-SIM.

The work focused on understanding how spoofing information is detected by the GPS receiver, how it is passed through the Here4 firmware and DroneCAN, and how it can ultimately be observed by ArduPilot and Mission Planner.

## Objectives

- Understand GPS spoofing detection in the ArduPilot ecosystem.
- Study relevant GPS and spoofing-related firmware.
- Analyse spoofing-related ArduPilot commits.
- Build custom ArduPilot firmware.
- Generate simulated GPS signals using GPS-SDR-SIM.
- Transmit simulated signals using HackRF One.
- Observe spoofed GPS data through Mission Planner.
- Trace spoofing-status information from the GPS receiver to the flight controller.
- Identify why spoofing levels were initially not appearing in Mission Planner.
- Investigate firmware changes required to propagate spoofing information.

## 1. Initial Study

The initial work involved studying the Cube Orange+ architecture, its applications, interfaces, STM32-based platform, and the ArduPilot software environment.

Relevant GPS and navigation firmware paths were then studied to understand how GPS information is handled by the flight controller.

## 3. Initial Spoofing Experiment

After configuring the environment and building the required custom ArduPilot firmware, simulated GPS signals were successfully transmitted.

Observed changes in Mission Planner included:

- GPS coordinates shifting toward the spoofed location.
- Changes in satellite count.
- Changes in HDOP values.

These observations confirmed that the spoofed signal was reaching the GPS receiver and influencing the reported navigation solution.

## 4. Spoofing Detection Investigation

Although spoofed coordinates were being received, the expected spoofing level was initially not appearing in Mission Planner.

The investigation therefore moved to the firmware and communication path, including:

- EKF3-related code
- u-blox GPS processing
- ArduPilot GPS handling
- Spoofing-related commits
- Here4 firmware
- DroneCAN communication

## 5. Key Finding: DroneCAN Data Path

The GPS module was communicating with the Cube Orange+ through DroneCAN.

```text
u-blox Receiver
      |
      v
Here4 Firmware
      |
      v
DroneCAN
      |
      v
Cube Orange+
      |
      v
Mission Planner
```

The documented finding was that the spoofing state generated by the u-blox receiver was not initially being included in the DroneCAN messages sent by the Here4 module.

Therefore:

```text
u-blox detects spoofing
        |
        v
Here4 receives spoofing state
        |
        v
DroneCAN message does not contain the state
        |
        v
Cube Orange+ does not receive the state
        |
        v
Mission Planner shows no spoofing level
```

The investigation therefore identified the DroneCAN communication path, rather than EKF3 itself, as the key issue in the missing spoofing-status information.

| Spoofing level | Status |

| Level 0 | Verified |
| Level 1 | Verified |

Level 2 and Level 3 testing require simultaneous transmission of conflicting GPS signals so that the receiver can be evaluated under conflicting-signal conditions.

## 9. Current Testing

The next phase is to use two HackRF devices to create real and spoofed GPS signal conditions.

The objective is to investigate higher spoofing-status cases and verify how the resulting status propagates through the Here4 firmware, DroneCAN, ArduPilot, and Mission Planner.

## 10. Key Findings

- Spoofed GPS coordinates were successfully received.
- Changes in satellite count and HDOP were observed.
- The missing spoofing-status information was investigated separately from GPS navigation measurements.
- The Here4 communicates with the Cube Orange+ through DroneCAN.
- The spoofing state generated by the u-blox receiver was initially not included in the DroneCAN message.
- Firmware changes were therefore investigated across the GPS, AP_Periph, DroneCAN, and Mission Planner reporting paths.
- Level 0 and Level 1 were verified; higher levels remain under testing.
